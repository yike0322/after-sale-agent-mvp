# 售后判定规则（演示数据）

> 本文为求职项目的虚构、去标识化规则，仅用于本地演示；不代表任何真实平台政策。

## 退款与异常的确定性优先级

1. `LOGISTICS_EXCEPTION`：不自动赔付，创建/保留物流异常工单，状态为 `WAIT_HUMAN`。
2. `RESTRICTED` 商品：不走自动退款，结论为 `FINISHED`，原因为受限品类需线下渠道处理。
3. 已付款但未签收（`PAID` 且 `received_at` 为空）：结论为 `FINISHED`，原因为未满足签收后退款评审条件。
4. 普通商品已签收（`NORMAL` + `RECEIVED`）：结论为 `WAIT_HUMAN`，仅表示“可进入人工退款审核”，绝不执行支付或退款动作。

## Agent 执行边界

- 对话 Agent 只做意图路由；订单、优惠券和规则信息必须通过受治理 Tool 取得。
- 规则结论由 Java 的确定性服务决定；模型仅可生成解释，不可改变结论。
- 工单步骤和 Tool 调用会落库为脱敏摘要，页面只能显示脱敏轨迹。
